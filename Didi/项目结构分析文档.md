# 滴滴出行平台项目结构分析文档

## 📋 项目概述

**项目名称**: Didi 网约车平台  
**技术栈**: Go + Kitex + Hertz + MySQL + Redis  
**架构模式**: 微服务架构  
**开发语言**: Go 1.24.4  

本项目是基于字节跳动开源框架 Kitex 和 Hertz 构建的网约车服务平台，采用现代化的微服务架构设计，支持用户叫车、司机接单、行程管理等完整业务流程。

---

## 🏗️ 整体架构分析

### 架构层次图
```
┌─────────────────────────────────────────────────────────────┐
│                        客户端层                             │
│                    (移动端/Web端)                           │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      业务逻辑层 (BIZ)                       │
│                     HTTP API Gateway                       │
│              (Hertz框架 + 路由 + 中间件)                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      RPC服务层                             │
│                   (Kitex微服务)                            │
│              User Service | Driver Service                 │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      数据访问层                             │
│                   MySQL + Redis                            │
└─────────────────────────────────────────────────────────────┘
```

### 技术架构特点
- **前后端分离**: BIZ层提供HTTP API，支持多种客户端
- **微服务架构**: 使用Kitex框架实现RPC服务拆分
- **高性能网关**: Hertz框架作为HTTP网关，性能优异
- **数据分层**: MySQL持久化存储，Redis缓存加速
- **代码生成**: 基于Thrift IDL自动生成RPC代码

## 🔍 核心模块深度分析

### 1. BIZ层 - 业务逻辑网关
**路径**: `biz/`  
**职责**: HTTP API网关，处理客户端请求，调用RPC服务  
**框架**: CloudWeGo Hertz  

```
biz/
├── main.go                       # 主程序入口 (HTTP服务器启动)
├── dal/                          # 数据访问抽象层
│   ├── config/                   # 配置管理
│   ├── global/                   # 全局变量
│   ├── inits/                    # 初始化逻辑
│   └── dev.yaml                  # 开发环境配置
├── handler/                      # HTTP请求处理器
│   ├── api/                      # API实现
│   │   ├── user.go              # 用户相关API (注册/登录/实名认证)
│   │   ├── driver.go            # 司机相关API (申请/管理)
│   │   └── wechat.go            # 微信相关API (支付/登录)
│   └── request/                  # 请求模型定义
│       ├── user.go              # 用户请求结构体
│       ├── driver.go            # 司机请求结构体
│       └── wechat.go            # 微信请求结构体
├── middleware/                   # HTTP中间件
│   └── jwt.go                   # JWT认证中间件
└── router/                       # 路由配置
    ├── router.go                # 主路由注册
    ├── user.go                  # 用户路由
    ├── driver.go                # 司机路由
    └── weChat.go                # 微信路由
```

**关键特性**:
- 基于Hertz的高性能HTTP服务
- JWT中间件提供认证授权
- 模块化路由设计，便于维护
- 请求/响应模型分离，代码清晰

### 2. RPC层 - 微服务集群
**路径**: `rpc/`  
**职责**: 核心业务逻辑实现，提供RPC服务  
**框架**: CloudWeGo Kitex  

```
rpc/
├── common/                       # 公共模块
│   ├── config/                   # 配置管理
│   ├── global/                   # 全局变量和连接池
│   ├── inits/                    # 服务初始化
│   ├── model/                    # 数据模型定义
│   │   ├── user.go              # 用户数据模型
│   │   ├── driver.go            # 司机数据模型
│   │   └── driver_application.go # 司机申请模型
│   └── dev.yaml                 # RPC服务配置 (MySQL/Redis连接)
├── user/                         # 用户微服务
│   ├── main.go                   # 用户服务启动入口
│   ├── handler.go                # 用户业务逻辑处理
│   ├── build.sh                  # 服务构建脚本
│   ├── kitex_info.yaml          # Kitex配置文件
│   └── script/bootstrap.sh       # 服务启动脚本
└── driver/                       # 司机微服务
    ├── main.go                   # 司机服务启动入口
    ├── handler.go                # 司机业务逻辑处理
    ├── build.sh                  # 服务构建脚本
    ├── kitex_info.yaml          # Kitex配置文件
    └── script/bootstrap.sh       # 服务启动脚本
```

**微服务设计优势**:
- **用户服务**: 处理注册、登录、实名认证等用户相关业务
- **司机服务**: 处理司机申请、审核、管理等司机相关业务
- **独立部署**: 每个服务可独立开发、测试、部署
- **水平扩展**: 可根据业务需求独立扩容

### 3. IDL层 - 接口定义
**路径**: `idl/`  
**职责**: 使用Thrift定义服务接口，确保跨语言兼容  

```
idl/
├── user.thrift                   # 用户服务接口定义
└── driver.thrift                 # 司机服务接口定义
```

**user.thrift 接口分析**:
```thrift
service UserServer {
    SendSmsResp SendSms(1: SendSmsReq req)           // 短信验证码发送
    LoginUserResp LoginUser(1: LoginUserReq req)      // 用户注册登录
    RealNameResp RealName(1: RealNameReq req)        // 实名认证
}
```

**driver.thrift 接口分析**:
```thrift
service driverServer {
    CallACarResp CallACar(1: CallACarReq req)        // 司机申请注册
}
```

```
    │       └── userserver.go    # 服务实现框架
    └── driver/                   # 司机服务生成代码
        ├── driver.go            # 数据结构定义
        ├── k-driver.go          # Kitex扩展
        ├── k-consts.go          # 常量定义

            ├── client.go        # 客户端代码
            ├── server.go        # 服务端接口

```

## 🚀 服务启动流程

### 1. BIZ层启动流程
```go
// biz/main.go
func main() {
    // 1. 初始化数据访问层
    _ "Didi/biz/dal/inits"
    
    // 2. 创建Hertz服务器
    h := server.Default(server.WithHostPorts("127.0.0.1:8080"))
    
    // 3. 注册路由
    router.Register(h)
    
    // 4. 启动HTTP服务
    h.Spin()
}
```

### 2. RPC服务启动流程
每个RPC服务都有独立的启动入口，通过Kitex框架启动：
- 用户服务: `rpc/user/main.go` (端口: 50051)
- 司机服务: `rpc/driver/main.go` (端口: 50052)

## 🔄 数据流转

### 典型请求流程
```
客户端请求 → Hertz网关 → JWT验证 → 路由分发 → Handler处理 
    ↓
调用RPC服务 → Kitex客户端 → RPC服务端 → 业务逻辑处理 
    ↓  
数据库操作 → GORM → MySQL/Redis → 返回结果 → 响应客户端
```
