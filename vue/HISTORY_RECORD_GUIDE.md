# 历史记录功能使用指南

## 功能概述

本打车平台已成功集成历史记录保存功能，调用后端 `/api/CreateHistoricalSearch` 接口。该功能只有登录用户才能使用，符合业务需求。

## 主要特性

### ✅ 已实现的功能

1. **登录状态检查**：只有登录用户才能保存历史记录
2. **完整参数传递**：向后端传递所有必要的位置信息
3. **错误处理**：妥善处理各种异常情况
4. **用户体验**：即使后端保存失败也不影响正常使用
5. **多页面支持**：首页和地址选择页都支持历史记录保存

### 🔧 接口参数

调用 `/api/CreateHistoricalSearch` 接口时传递以下参数：

```typescript
{
  addrName: string,      // 地址名称（如："上海浦东机场"）
  idAddr: string,        // 区域信息（如："浦东新区"）
  lat: number,           // 纬度坐标
  lng: number,           // 经度坐标
  searchTime: string     // 搜索时间（ISO格式）
}
```

### 🔐 认证机制

- 使用 localStorage 中的 `token` 进行身份验证
- API 请求头自动携带 `Authorization: ${token}`
- Token 过期时会自动跳转登录页面

## 触发时机

历史记录会在以下情况下自动保存：

### 首页 (Home.vue)
- 用户选择起点地址时
- 用户选择终点地址时
- 通过地址搜索确认地址时

### 地址选择页 (AddressInput.vue)
- 用户选择任何地点时
- 从搜索结果中选择地址时
- 从热门地点中选择时

## 错误处理策略

### 1. 登录状态检查
```typescript
if (!isLoggedIn.value) {
  console.log('用户未登录，跳过保存历史记录')
  return
}
```

### 2. API 错误处理
- **401/403**：Token过期，清除本地存储并跳转登录
- **500**：服务器错误，显示友好提示
- **网络错误**：显示网络异常提示

### 3. 用户体验保障
即使后端保存失败，也会：
- 更新本地历史记录显示
- 保存到 localStorage 作为备份
- 不阻塞用户正常操作流程

## 后端接口要求

确保后端 `/api/CreateHistoricalSearch` 接口：

### 请求格式
```
POST /api/CreateHistoricalSearch
Content-Type: application/json
Authorization: ${token}

{
  "addrName": "上海浦东机场",
  "idAddr": "浦东新区", 
  "lat": 31.1434,
  "lng": 121.8052,
  "searchTime": "2024-01-15T10:30:00.000Z"
}
```

### 响应格式
```json
{
  "code": 200,
  "message": "历史记录保存成功",
  "data": null
}
```

## 安全考虑

1. **认证验证**：所有请求都需要有效的 token
2. **参数验证**：后端应验证所有必需参数
3. **权限控制**：确保用户只能保存自己的历史记录
4. **数据清理**：定期清理过期的历史记录

## 常见问题排查

### Q: 为什么历史记录没有保存？
A: 检查以下几点：
1. 用户是否已登录（localStorage 中有 token）
2. 后端服务是否正常运行在 8888 端口
3. Token 是否有效（未过期）
4. 控制台是否有错误信息

### Q: API 调用失败怎么办？
A: 系统已内置容错机制：
1. 会在控制台记录详细错误信息
2. 本地历史记录仍会正常更新
3. 不会影响用户的正常使用流程

### Q: 如何验证功能正常？
A: 查看浏览器控制台输出：
- 看到 `💾 准备保存历史搜索记录:` 表示开始保存
- 看到 `✅ 历史记录保存成功` 表示保存成功
- Network 面板应能看到对应的 POST 请求
